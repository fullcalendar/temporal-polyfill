
# ENV-ISSUE
# Node 18 through 20, native Intl.DateTimeFormat can return incorrect ancient
# BCE iso8601 date parts for America/Vancouver. The polyfill computes
# named-zone offsets by formatting an instant to local
# year/month/day/hour/minute/second parts and subtracting the original epoch
# time; the bad host date parts produce a nonsensical +687:47:32 offset instead
# of the expected pre-standard-time -08:12:28.
#
# Node 16 does not reproduce this particular host-Intl failure, and Node 22's
# newer ICU data returns the expected fields.
